# Localization

English is the catalogue key: `t('Rooms')` looks up `Rooms` in the active
language and falls back to the key, so a missing translation renders English and
nothing breaks. That makes an untranslated string invisible in review, which is
why coverage is measured rather than assumed.

## Languages shipped

Five UI languages: English (`en`), Spanish (`es`), German (`de`), French (`fr`)
and Turkish (`tr`). **Settings → Appearance → Language** takes the system
language or one of them by name; `normalizeLanguage()` resolves any other system
locale to English, so an unsupported machine degrades to English rather than to a
partly translated screen. English is the key, so the other four are catalogues
that answer for the sentences they have translated.

| Language | Where its copy lives |
| -------- | -------------------- |
| English (`en`) | Inline in `src/lib/i18n.tsx` and the per-feature modules — it is the key catalogue, not a translation. |
| Spanish (`es`), German (`de`), French (`fr`) | A block per language in `i18n.tsx`, plus `i18n-sweep-<lang>.ts` for the swept backlog and the per-feature modules. |
| Turkish (`tr`) | Its own catalogue, `src/lib/i18n-tr.ts`, merged last so it wins over any per-locale block. |

## How it is measured

`tests/i18n-coverage.test.ts` walks every `.ts`/`.tsx` file under `src/`, collects
each literal passed to `t(...)`, and asks each catalogue whether it translates
that key. It runs as part of `pnpm test`.

Two assertions hold the line:

- **A ratchet.** The number of untranslated keys may fall but never rise. Adding
  an English string without its translations fails the run.
- **This release's strings.** Every string added by the player, rooms, typography,
  currency and Lexium work is listed explicitly and must exist in `es`, `de` and
  `fr`. Turkish is held by its own ratchet instead, so new copy can land there
  progressively without blocking a release.

New copy lives in a module per feature (`i18n-lifecycle.ts`, `i18n-currency.ts`,
`i18n-session.ts`, …) and is merged last in `makeI18n`, so a key is defined once
instead of inside every language block.

## Current state

Measured by the coverage audit at 0.9.5-hotfix.7, over 2,002 distinct keys
collected from `src/`:

| Language | Untranslated (measured) | Ratchet limit |
| -------- | ----------------------- | ------------- |
| English (`en`) | 0 | — (the source catalogue) |
| Spanish (`es`) | 41 | 41 |
| German (`de`) | 68 | 68 |
| French (`fr`) | 56 | 56 |
| Turkish (`tr`) | 1,282 | 1,291 |

Spanish, German and French sit exactly on their limits. Turkish is a different
kind of number — a backlog being worked off rather than a list of tokens — and
is described under [Turkish](#turkish).

The historical backlog is swept. `i18n-sweep-es.ts`, `i18n-sweep-de.ts` and
`i18n-sweep-fr.ts` carry every string the audit reported missing, and they are
merged *first*, so a feature module that later owns a key still wins. That sweep
took the counts from 383/408/395 to 41/68/56.

What is left is deliberately untranslated, and the ratchet is pinned to it:

- product and protocol tokens (`SHA-256`, `STUN / TURN`, `VEXIUM CORE`, `CPU`,
  `URL`, `BitTorrent`), which a translated build still shows verbatim;
- units and numbers (`250 ml`, `{value} kcal`, `{total} XP`);
- names (`YOUTUBE`, `Lexium`, `Chromium`, `Chrome Web Store`);
- words already correct in the target language (`Color` and `Hardware` in
  Spanish, `Browser`, `Desktop`, `Downloads`, `Name`, `Text`, `Update` and
  `Pop-up` in German, `Accent` and `Architecture` in French).

A reviewer can confirm the list by lowering the limit and reading the failure;
`docs/TESTING.md` records the run.

## Rules the audit follows

- Translate what a person reads, not what a parser reads: codes, URLs, file names,
  provider error payloads and technical identifiers stay as they are.
- Interpolation uses named placeholders (`{count}`, `{name}`, `{status}`), never
  concatenation, so a language can reorder them.
- Counts use an explicit singular/plural string pair (`1 track` / `{count} tracks`)
  rather than a suffix, because the shipped languages pluralise differently once
  a sentence grows — Turkish included, where the ending follows vowel harmony
  (`-ler` / `-lar`) instead of a fixed `-s`.
- Date and time formatting goes through `toLocaleString`/`toLocaleDateString`
  with the active locale, not a hand-built pattern.
- A longer translation must not clip: the settings rows and the player toolbar
  were checked at 130 % text scale in Spanish, German and French. Turkish has
  not been through that sweep yet, and the paragraphs it has not translated are
  still English, so a Turkish build is not yet carrying its own longest strings.

## Not covered

- Strings produced by the main process (extension installation results, error
  payloads) are English at source; `extensionMessage()` translates the stable
  messages, but a raw OS error remains English.
- Server responses (Whisper, LibreTranslate, Spotify) are shown as the server
  wrote them, prefixed by a translated label.
- Right-to-left languages are not supported yet.

## The phone companion is separate on purpose

Kryvex Link's phone page (`src/companion/`) is a second bundle, so it carries its
own small table (`src/companion/strings.ts`, English/Spanish/German/French/Turkish)
and reads `navigator.language` once instead of pulling the whole desktop
catalogue onto a phone. Turkish is **complete** there rather than progressive:
the table is small enough to translate in one pass, and a phone that has just
paired should not meet a half-English page. The `satisfies` clause on the table
makes a missing `tr` entry a type error, and `tests/link-companion.test.ts`
checks the locale mapping (`tr-TR` and `TR-tr` to `tr`, `az` to English). Its strings go through a local helper rather than the desktop's
`t()`, so they are deliberately outside the ratchet above; a key with no entry
falls back to English. The x534 tile caption and the product name are brand
marks and stay identical in every language.

## Turkish

Turkish (`tr`, **Türkçe**) is the fifth UI language and the first that ships
knowingly partial. It has its own catalogue, `src/lib/i18n-tr.ts`, rather than a
block in `i18n.tsx`, and it is merged last so it wins over every per-locale
block. The language blocks are typed `Partial<Record<…>>` now: a language that
has not written a block contributes nothing, and `makeI18n` reads every block
through a `pick()` helper, so a missing language can never throw.

What the first pass covers: navigation and the shell, Home board furniture and
the whole clock card, the Workspace and its window controls, service controls
and the secret-services gate, browser and download labels, player and playlist
labels, Rooms and the phone link, the emulator and disk tools, the Vexium
labels, and the common actions, states and confirmations. Long explanatory
paragraphs — settings descriptions, release notes, error explanations — are
still English and fall back to the key.

Two ratchets guard it. `TURKISH_BACKLOG` is pinned at 1291, and the audit at
this release measures **1,282 of 1,951 keys** falling back to English — the
catalogue grew from 1,685 keys while the backlog fell, so the two numbers are
not directly comparable, and only the count may fall. The second is the
placeholder audit: a test walks every non-English catalogue and fails if a
translation drops or renames an interpolation token, which is how a hand-written
string loses `{city}` and renders it literally. That audit is also the standing
check on Spanish, German and French.
